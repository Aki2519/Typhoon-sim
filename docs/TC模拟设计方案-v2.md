## 0. 范围与总原则

### 0.1 本方案要解决的问题

| 层 | 现状 | 问题 |
|---|---|---|
| **积分框架** | 积分步 10 分钟、环境步 1/3/6/12/24h 两套 | 表述混乱;10 分钟并不带来登陆精度;白白多算 36 倍 |
| **环境场** | 12 个月基态线性插值 | 月内连续变形,没有"环流型维持"的语义;缺季节内变率 |

| **生成** | 观测密度场抽样 | 不分类;不命名 |
| **显示** | `int(round(vmax))` | 整数,抹掉精度 |
| **工程** | `simulator/wrf/` 在主程序内 | 未解耦 |

### 0.2 总原则(用户定的纪律,继续执行)

1. 每步**先渲染目视再下结论**
2. **单日**,不用时段平均
3. 不抽点读数代替看图
4. netCDF 一律防有限值 `_FillValue`
5. 每步跑回归测试(当前 **498 项,必须全绿**)
6. 临时诊断文件跑完即删,产物归档 `output/sim/`
7. **离线**:真实数据只在训练时用,烘进 `simulator/env/model/*.npz`

### 0.3 一个反复出现的教训(本方案的方法论前提)

前 18 轮挖出的 12 个 bug 里,**有 7 个是"系数按旧合成场定标、换数据源后没重标"**:

| 系数 | 原值 | 标定值 | 偏差 |
|---|---|---|---|
| SST 冷却 | 0.04 | 0.0015 | 强 30 倍 |

## 1. 时间步长与积分框架

### 1.1 单一步长

```
DT = envStepH           # 步长上限 6h
                        # 可选 1 / 3 / 6 h,默认 6h
```

**删掉 12h / 24h 选项**(UI 与 `ENV_STEPS` 同步)。

现在的 10 分钟积分步来自粒子/渲染系统,**对台风内核没有物理必要**:
- 强度 ODE 在环境冻结期内是自治的,10 分钟积 36 步 ≡ 6 小时积 1 步(数学等价,纯冗余)
- 运动滞后 τ=3h,6h 步长下 `α = 1−exp(−6/3) = 0.865`,稳定
- 强度 `dt/τ = 6/55 = 0.11`,Euler 精度足够

**唯一真正的风险是"跨过一条窄海岸线"和"尾流变成分离的圆点",而这两件事用几何方法解决,不是靠缩小步长。**

### 1.2 登陆:线段与陆地场几何求交

```
输入: 步起点 p0=(lon0,lat0)、步终点 p1=(lon1,lat1)、陆地比例场 land(r)

1. 沿线段均匀采样 N 点,N = max(8, ceil(弧长 / (0.5·格宽)))
2. 找 land 从 <0.3 跨到 >0.3 的第一段 [pa, pb]
3. 在 [pa, pb] 内二分 ~10 次 → 精确交点
4. 返回交点位置 + 交点到 p1 的剩余距离
```

**6h 一步、10 kt 速度下线段长 60nm,分 4~8 点即可覆盖。任何步长下都不会漏。**

### 1.3 尾流:沿线段沉积

把 `deposit_gauss` 在线段上按 `ceil(|V|·dt / (0.5·RMW))` 个点调用。
6h / 10 kt / RMW 40nm → 3 个点。尾流连成一条**带**,不是一串圆点。

### 1.4 需要跟着改的

| 项 | 现状 | 改法 |
|---|---|---|
| 生成检查 | 固定每 6h | 每步(与步长一致) |
| 日变化项 | 在 `env_update` 里按钟点采样 | 6h 步长采 4 点,够用;若将来放宽步长再解析积分 |
| `_envVer` / hist | 每步 | 不变 |

### 1.5 收益

| | 现在 | 改后 |
|---|---|---|
| 一年回放 | ~15 分钟 | **~5 分钟** |
| 登陆检测 | 采样,可能漏 | **几何求交,不漏** |
| 尾流 | 步长大时是点串 | **沿线段连续** |

## 2. 环境场:环流重构(A + B)

### 2.1 为什么放弃"半月切换"方案

用户的原始直觉是对的:**真实环流有持续性** —— 副高会以一个有形状的型维持一两周再转型,而月内线性插值让它连续变形(幻灯片淡入淡出)。

但"半月阶梯"有三个问题:
1. **15 天是人为尺度** —— 真实低频变率是 10–60 天的**连续谱**
2. **段间怎么过渡** —— 硬切不连续,插值又退回原样
3. **"进动"要拍一个 ω** —— 除非从数据反推

**替代方案:用真实的低频环流型(regimes)。**

### 2.2 分解式

```
field(t) = A. clim_harmonic(doy)              # 平滑年循环
         + B. Σ_r pattern_r · PC_r(t)         # 真实低频环流型(10–60 天)
         + C. Σ_m pattern_m · idx_m(t)        # 年际(ENSO/PDO/AMO…, 已有 12 模态)
         + D. MJO(t)                          # 季节内(已有逐日 RMM)
         + E. synoptic(t) + mesoscale(t)      # 高频(随机, 谱已标定)
```

### 2.3 A:谐波年循环(零额外数据)

对每月基态拟合**前 2–4 个年谐波**:

```
base(doy) = a0 + Σ_{k=1..4} [a_k·cos(2πk·doy/365) + b_k·sin(2πk·doy/365)]
```

- 连续、光滑、任意日序可求值
- 真实年循环的主要能量就在前 2 个谐波
- **替代**现在 `solver._month_weight` 的线性插值

### 2.4 B:真实低频环流型(核心)

```
1. 取 NCEP/NCAR 逐日 500hPa 位势高度 Z500(1948–2026, 2.5°)
2. 去季节循环 → 异常场
3. 对异常场做低通(10 天滑动)→ 只保留低频部分
4. EOF 分解 → 前 4–6 个 EOF = 真实环流型(PNA / WP / EA / AO…)
5. 对应的 PC 时间序列 = 真实的逐日序列(1948–2026 全有)
6. 把 u/v(850/500/200)、切变、SST、OHC 对 PCs 做回归 → 每个型的空间响应型
```

**运行时:**
```
field(t) = clim_harmonic + Σ_r pattern_r · PC_r(t)
```

**为什么比半月好:**

| | 半月方案 | 环流型方案 |
|---|---|---|
| 人为尺度 | 有(15 天) | **无** |
| 持续性来源 | 拍一个 ω | **真实 PC 自相关(红谱)** |
| 日期准确性 | 只到半月 | **逐日** |
| 数据量 | 24 场/年(全变量) | **1 变量 1 层** |
| 顺带解决强度尾部 | 否 | **是**(见 §3.7) |

### 2.5 未来日期的 PC 怎么来

- **1948–2026**:直接用真实 PC
- **2027+**(如 2097):两种可选
  - **AR(p) 外推**:用真实 PC 拟合 AR(p),保留真实自相关
  - **历史类比重采样**:随机挑一个历史年份的 PC 段拼接 —— 天然保留真实持续性,不会漂出训练范围
  - **默认用后者**,因为它不会产生物理上不存在的极端值

### 2.6 存储

```
simulator/env/model/regimes.npz
  eof           : (n_r, nlat, nlon)           # EOF 空间型 (Z500)
  pc            : (nday, n_r)                 # 逐日 PC (1948-2026)
  day_index     : (nday,)                     # 对应日序
  resp_<var>    : (n_r, nlat, nlon)           # u850/v850/u200/... 对 PC 的回归型
```

体积:PC 约 700 KB,响应型 6 型 × 12 变量 × 73×144 × 4B ≈ 3 MB。**很小。**

### 2.7 数据抓取

| 数据 | 用途 | 体积 |
|---|---|---|
| 逐日 Z500(1948–2026, 2.5°) | EOF / PC | ~1.2 GB(不落盘,流式算完只存 PC) |
| 逐日 u/v 850/200(1991–2020) | 回归响应型 | ~800 MB |
| 逐日 SST(可选) | 回归响应型 | 复用已有 OISST/CMEMS |

PSL 的 OPeNDAP 可直接读,无需下载整文件。

## 3. 强度系统重构(本方案核心)

### 3.1 为什么要推翻现有的

现在的内核:
```python
dV += (vpi - vmax) / tau                  # 向 MPI 松弛
dV += gauss() * 1.35 * (0.5 + vmax/155)   # 高斯噪声
if RI 条件 and rng() < p:                 # ← 开一个 20-34h 的窗口
    dV += 2.24                            #    窗口内额外 +2.24 kt/h
tc['rmw'] = rmw_from_v(tc['vmax'])        # ← RMW 是 vmax 的纯函数
```

两个根本问题:
1. **`riCD` 那套没有对应的物理过程** —— 它是"为了造出右偏分布"而拍的机制
2. **RMW 没有演化** —— 而帖子(《云卷眼是否限制高强度?》)的结论恰恰是:**上限由 RMW 决定**

### 3.2 帖子立住的物理(本模型要编码的对象)

| # | 结论 | 对本模型的含义 |
|---|---|---|
| 1 | BF(卷眼)/ CF(塌眼)**不是二分,是连续谱**;两者都是靠卷绕构建眼墙 | **不设"卷眼/塌眼"状态机**,改一个连续量 |
| 2 | 真正的控制变量是**初始 RMW / 外核惯性稳定度径向梯度** | RMW 必须是**预报量** |
| 3 | 小 RMW → 入流穿透到 RMW 内 → 加热集中 → 增强快、上限高 | `η = η(RMW)`,越小越接近 1 |
| 4 | 小 RMW → 对流破顶集中在更小半径 → 把**平流层下层高位温空气**泵进暖心 → 气压剧降 | 同上,并给"半卷半塌"提供机制 |
| 5 | **ERC 级联是上限杀手**:每次置换眼径更大、上限更低("剥洋葱") | ERC 作为骨架 |
| 6 | **适当风切/干空气反而有利**(抑制雨带);CF 环境的 RH 和 CAPE **都更低** | 雨带项对风切/干空气**非单调** |
| 7 | CF 多发秋季、BF 多发夏季;CF 常来自**东风波**,BF 常来自**季风低压** | 生成分类接初始 RMW |
| 8 | **EMBC**(底层眼完整、高层无眼)被压缩着,风速积累够或风切退去 → 弹簧释放 | 一个"压缩-释放"状态 |
| 9 | **半卷半塌**(Zeb 1998 等):BF 途中惯性屏障被突破 → 深对流填塞旧眼 → 增强惊人 | 一次罕见的屏障突破跃迁 |

**观测锚点(可直接用于标定):**

| 量 | 值 |
|---|---|
| CF vs BF 最低气压差 | CF 低 >12 hPa |
| CF vs BF 加深率 | CF 快 10.8 hPa/天 |
| CF vs BF 增强率 | CF 快 8.2 kt/天 |
| 达到 RI 的比例 | CF **91%** / BF **59%** |
| 塌陷风速区间 | 一般 55–120 kt,多发 **85–110 kt** |
| 高风切下可不塌陷 | 有 130 kt 的 EMBC 飓风(2020 北大)、125 kt(2002 海神) |

### 3.3 状态变量

```python
tc['vmax']       # 强度 (kt, 内部 0.1 kt 精度)
tc['rmw']        # 最大风速半径 (nm) —— 改为预报量
tc['core_org']   # 核心组织度 ∈ [0,1] —— 替代 BF/CF 二分
tc['embc']       # 嵌匿中心标志(bool)
tc['erc']        # 置换状态(dict 或 None) —— 骨架
tc['pmin']       # 由 vmax + rmw 诊断
```

### 3.4 主方程

```
V_ceiling = MPI(SST, OHC, 流出) · η(RMW) · η_org(core_org)      # 上限
dV/dt     = (V_ceiling − V) / τ + 随机项 + 释放项

d(RMW)/dt = −c_contract · (V/V_ceiling) · core_org              # 增强时收缩
            + c_band · A(RMW, 环境)                              # 雨带撑开
            + ΔRMW|_ERC                                          # 置换跳跃

d(core_org)/dt = k1 · (集中加热) − k2 · A − k3 · (风切散乱)
```

其中 **`η(RMW)` 是"外核惯性稳定度屏障"的宏观表达**:

```
η(RMW) = η_min + (1 − η_min) · exp(−(RMW / R_ref)^p)
```

RMW → 0 时 η → 1(理论上限);RMW 大时 η → η_min。
`R_ref` 与 `p` 由观测的峰值分布标定。

### 3.5 骨架:ERC 级联

**这是整个模型的骨架**,因为它是唯一一个离散、可观测、机制清楚、有累积效应的过程。

```
雨带活动 A = f(低层湿度, SST, 外围风速, 环境 PV)
            · (1 − 抑制(风切, 干空气))        # ← 注意: 抑制项使 A 减小
            + 季风槽/ITCZ 出身的额外项          # 环境 PV 环合并(帖子 26.8.24 补充)

触发条件:  A > A_crit  且  V > V_crit  且  cooldown 已过

ERC 三阶段(总时长 2–3 天):
  阶段1 外眼生成   (~12h):  外眼在 2.2–3.0 × RMW 处形成
  阶段2 MOAT      (~18h):  内眼被隔绝, V 下降 15–25%
  阶段3 外眼收缩   (~24h):  外眼向内收缩, 新 RMW ← 外眼半径

完成:  RMW 增大 → η(RMW) 下降 → V_ceiling 下降
       cooldown 重置(60–160h)
```

**"眼径越换越大、上限越换越低"是 RMW 演化的自然结果,不需要额外加规则。**

环境若持续产生雨带 → 置换重复 → 这就是"剥洋葱"。

### 3.6 三个状态跃迁(替代 `riCD`)

| 机制 | 触发 | 效果 |
|---|---|---|
| **EMBC 释放** | `embc` 为真 且(vmax > 阈值 或 风切 < 阈值) | `dV += 释放强度`,`core_org += 跳跃`,`embc = False` |
| **屏障突破**(半卷半塌) | `core_org` 低 且 环境骤好(风切骤降/流出转好),小概率 | `core_org` 跳到高值,RMW 快速收缩 → 强正反馈 |
| **EMBC 形成** | 底层眼完整 且 高层无眼(受风切或下沉不足) | `embc = True`(强度暂缓,蓄势) |

**这三个都有触发条件、前置状态和物理含义,不是"开窗口加固定值"。**

### 3.7 顺带解决强度尾部

前 18 轮的遗留问题:**P75/P95 比观测低 9/26 kt**,根因是"月平均环境场缺季节内变率,所有风暴看到的环境趋同,峰值分布太窄"。

**§2 的环流型 B 正好提供这个变率** —— PC 的 10–60 天时间尺度就是"RI 窗口"的时间尺度。B 做完,尾部应该会一起改善。

### 3.8 与现有代码的接口

| 现有 | 处理 |
|---|---|
| `riCD` / `tc['ri']` | **删除** |
| `rmw_from_v(v)` | 保留为**初始值**生成器与诊断对照,不再每步调用 |
| `alpha_outer` / `radius_at_wind` | 保留(风场廓线),但 `alpha_outer` 上一轮已按 T5 重标 |
| `vpi` | 改名 `MPI`,进入 `V_ceiling` |
| `erc` dict | 扩成三阶段状态机 |

## 4. 生成系统

### 4.1 分类(用户需求 4)

现在的密度场把**所有**生成点混在一起统计。真实的生成至少这几类:

| 类别 | 判别特征(可用环境场自动分类) | 初始 RMW / core_org |
|---|---|---|
| **ITCZ / 季风槽** | 低层气旋式切变 + 高 SST + 赤道辐合带纬度 | 中 |
| **季风低压** | 低层**强西风** + 深厚湿层 + 槽内 | **大 RMW / 低 core_org** → 走 BF |
| **反向季风槽(ROT)** | 东风波叠加 + 槽轴反斜 | 中偏小 |
| **冷涡 / 切断低压转热** | 高空冷心 + 低 SST 也能生成 + 副热带 | 中 |
| **EX / SS 转热** | 轨迹前段有温带/变性阶段 | 大 |
| **东风波** | 环境更干、初始尺寸更小、涡度径向梯度更大 | **小 RMW / 高 core_org** → 走 CF |

**观测依据(帖子引的陈&吴 2022):** CF 常有东风波特征、环境更干、初始尺寸更小、涡度径向梯度更大;BF 有季风低压结构、环境更湿、初始尺寸更大、涡度剖面更平坦。

**数据线索:** `官评` 里那两个没识别的字段 `[22]`(E/L/C)和 `[28]`(D/M/S)**很可能就是类别/阶段标记**。若确认,可直接用观测标注做分类统计,不必靠环境场反推。

> 实测锚点:2026 季首个命名台风是 **Nokaen**(第 3 套第 6 个,2026-01-16),
> 紧接 2025 季末尾的 Koto。三条独立季节序列互证:
> 2023 Jelawat(套1#8) → 2024 Ewiniar(套1#9);2024 Pabuk(套2#6) → 2025 Wutip(套2#7);
> 2025 Halong(套2#28) → 2026 Nokaen(套3#6)。
> 所以数据结构里存的是 `anchor = {year:2026, list_index:2, name_index:5, name:"Nokaen"}`,
> 而**不是**"年 → 表"的映射。

**算法改为"全局指针"形式:**

```
名表展平成 140 个名字的环形序列, 指针 p ∈ [0,140)
anchor: 2026-01-16 时 p = 2×28 + 5 = 61(指向 Nokaen)

求目标时刻 (Y, M, D) 的起始指针:
  1. 算出 anchor 到目标之间"跨过了多少个命名"
  2. 往前(Y < 2026): 用观测的逐次命名时刻(xrq/官评 有确切日期)直接数
  3. 往后(Y > 2026): 用气候平均 N̄ 与季节核密度 P(doy) 累加
  4. p_target = (61 + Δ) mod 140
```

**关键改进**:因为观测里有**每一次命名的确切日期**,对于历史年份可以**直接数**出指针,不需要"每年平均个数 × 季节比例"这种估计。估计法只在**未来年份**(如 2097)才用。

**未来年份的估计法**(仍需):

```
期望已命名数 = N̄ × ∫P(doy) d(doy)     (从年初积到当前日序)
N̄ 按洋区统计(WPAC ≈ 25-30/年)
P(doy) = 历史命名时刻的核密度(台风季集中 7–10 月)
```

**其他洋区**:
- **AL**:NHC 明写 2026 用第 1 套、2032 复用同套 → `{2026, list_index:0}` ✓ **一年一套成立**
- **EP**:同 AL,6 套轮换 ✓
- **CP**:2026 首个是 Lala(第 1 套第 6 个)—— 也不是第 1 个,需按实测锚点
- **IO / SH**:单一循环表,直接用全局指针

## 5. 运动系统

### 5.1 藤原(用户需求 5)

**现在的实现有毛病:**
```python
_fu += vortex_wind(o, ...) * 0.5      # 邻居涡旋在本点的切向风
if hypot(_fu,_fv) > 3.0: 按比例缩到 3kt   # ← 硬封顶
```
三个问题:
1. 封的是"引导气流的叠加量",不是"互旋漂移" —— 物理上不是一回事
2. 方向仍是邻居的切向风,对 1000km 以上不对
3. **不随距离衰减到位** —— 1200km 处本该几乎为零

**改成直接给位置漂移:**
```
V_drift = C · (Vmax_o/50) · (RMW_o / d)² · 50 kt     # 二元互旋的经典标度
方向    = 绕邻居涡旋的切向
门限    = d < 800 km  且  两者强度比 < 3
```
**`d⁻²` 让远距离自然归零,不需要硬封顶。**

### 5.2 高空反气旋风切(用户需求 6)

用户指出:**高反中心切变低、附近切变高**,成熟台风必定自带一个中心高反。这个应该能在风切图上直接看出来。

**验证方法(下一步就做):**
- 从 `miwu` 取成熟台风(vmax ≥ 96 kt)位置
- 用真实 NCEP 切变在这些点上做**半径-方位合成**
- 看是否呈现"中心低、四周高"的环状结构

**若验证成立**,在 `env['shear']` 上叠加:
```
shear_eff(r) = shear_env(r) · (1 − 0.6·exp(−(r/R_a)²))        # 中心降低
             + 2.5 · exp(−((r − 1.8·R_a)/R_a)²)                # 环状增强
```
仅当 `vmax > 阈值` 且高反成熟时施加。

### 5.3 β 漂移的两难(遗留)

**现状**:西太需要 9.6° 纬跨、东太只需要 6°,而 β 是全局常数(现取 2.9 kt)。

**正解**:让极向运动主要来自**引导气流的转向**(副高西侧),而不是夸大的 β。这需要在 §2 的环流型落地后重新审视 —— 真实的低频环流型应该能提供更真实的转向。

| 模态覆盖 | `sim_mode_override` + `cfg` | `params['modeOverride']` | — |

1. 显示/开关类设置的权威是**应用属性**(镜像 cfg, 跨会话记住), `sim_v4` 只是
   渲染读取的副本; 由 `_SIM_DISPLAY_KEYS` + `_sim_display` / `_sim_set_display` 统一。
2. 自然生成/数据环境只有**一个实现**(`_sim_toggle_natural_gen` /
   `_sim_toggle_data_mode`), 键盘与面板共用。
3. 面板的 `_get(key)` 必须与 draw 用同一个数据源(否则显示与 `_get()` 打架)。
4. **档位名是目标不是承诺**: 快档(50/100ms)会撞 `env_update` 地板, 慢档(2s/5s)
   必然超 800ms 上限; 信息框同时显示实测与目标, 超限告警单独占一行(同一行会被
   350px 框截断, 离屏渲染确认过)。
5. 快档不是"纯提速": `hold=16/3` 把大尺度场冻结 96h/18h, `quality=0` 关掉
   mesoscale eddy/noise —— 换档会改变模拟出的天气。默认 400ms 档是全物理参考。
6. `PRECISION_HARD_MS = 1000`(硬上限)目前**没有任何引用**, 唯一生效的是
   `PRECISION_CAP_MS = 800`(只用于 UI 告警)。

## 附录 E · 自动降速与"模拟时间对齐"(2026-09-19)

### 速度 vs 步长(经常被混的两个旋钮)

| 旋钮 | 在哪 | 含义 |
|---|---|---|
| **模拟速度** `sp` | 全局速度条 / `+ - ← → X` 键 | **播放倍速**。定义: 1× = 每秒 6 个**积分步**; 积分步长=环境步长, 所以 6h 步时 1× ≈ 36 模拟小时/实时秒(1h 步时 1× = 6 h/s —— 这个换算写在速度条上) |
| **环境步长** `envStepH` | 面板"环境步长"行 / 起始时间对话框 | **物理分辨率**: 环境场重建间隔 1/3/6h(上限 6h)。同时就是积分步长, 与播放快慢无关 |
| **模拟精度** | 面板"模拟精度"行 | 每 6h 模拟时间的墙钟成本档位(50ms…5s), 决定每步多贵、多准 |

### 自动降速(用户要求: 自动降速, 保证模拟时间对齐)

1. **内步分帧**: `core.sim_step(sim, dt, max_inner=k)` 一次最多跑 k 个内步, 余下
   记在 `sim['_pendStep']`。每帧只跑预算内(`SIM_FRAME_BUDGET_MS = 200`)的 1-2 个
   内步 → 2s/5s 档不再一帧冻 2-5 s。
   **轨迹逐位不变**(`tests/test_sim_throttle.py` 钉住: 分帧与一口气跑, t/台风
   vmax/pmin/lat/lon/track 长度全部一致)—— 所以"模拟时间对齐"成立: 墙上慢,
   钟上不差, 一小时都不跳。
2. **欠账封顶一个积分步**: 机器吃不下时把速度降下来, 而不是无限累积欠账
   (旧实现会一直满负荷狂追, 界面上的倍速与实际完全脱钩)。
3. **如实显示**: 速度条上方红字显示"请求倍速 → 实测有效倍速"(3 s 窗口平滑,
   上限钳到请求值, 见 `ControlPanel.draw` 的 `_sp_rate_cache`)。

## 附录 G · 2026-09-19 二轮反馈(严重问题)处置

### 最严重的一个: 环境场模型被静默丢弃

`envmodel/solver._regime_anomaly` 查响应表时用的是核心侧的原名(`u850`), 而训练产物的
键是 `resp_uwnd850`; 后段的 `T['resp'][field_name]` 于是抛 `KeyError`。这个异常被
`build_env_fields` 的 `except Exception: _model = None` 吞掉 —— **整套环境场模型
(基态 + 模态 + 增暖 + 环流型)全部失效, 静默回落到旧的合成库**。

用户看到的现象与它的关系:

* **"海温变成普通的递减"** —— 旧合成库在 13N/130E 的 3 月气候态是 21.5 °C(真实
  27.4), 年内振幅 7.9 °C(真实约 2); 模型基态是 27.9 °C 且带真实二维结构;
* 热带 MPI 掉到 8-15 kt ⇒ **没有系统能生成/增强**("生成就是 TS"的一半原因);
* 风切/湿度/气压/风场同时退回旧库或解析场。

处置: `_regime_anomaly` 先解析出真实键(`u850` → `resp_uwnd850`)再取表; 并让
`build_env_fields` 在模型失败时把原因写进 `dataWarn`(不再静默降级)。
