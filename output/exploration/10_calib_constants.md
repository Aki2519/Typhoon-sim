#### 3.1.2 三方证据的冲突点

**冲突 1：注释 vs 常数（方向相反）**

`core.py:2532-2534` 现状：
```
#: 向 MPI 逼近的**时间尺度**(小时)。观测反推: V=40kt、MPI≈120kt 时 24h Δvmax
#: 只有 +3.2kt ⇒ tau_eff ≈ 600h; 早期写 38h 快了 16 倍("快涨快死")。增强慢、减弱更慢
#: (观测 V 80-110 时 24h 掉 -9.1kt), 所以分开取。
TAU_INTENSIFY_H = 38.0
```
注释说"38h 快了 16 倍"（即应该慢 16 倍 ≈ 600h），而常数**就是 38**。

**算术核对（实测）**：`dV = gap/tau`，3.2kt/24h = 0.1333 kt/h，gap = 120−40 = 80kt ⇒ tau = 80/0.1333 = **600.0h** ✓ 注释的算术没错。而 600/38 = **15.79 ≈ 16** ✓ 也自洽。

⇒ 所以注释本身是一段**自洽的、主张 tau 应取 ~600h 的论证**。而它下面那行常数是 38 —— 注释从未随常数回退而更新。ROUND_LOG:969 证明**第51轮时这段注释已经存在**（当时常数是 68）。

**冲突 2：注释的主张 vs 轮次29 的实测方向**

| | 注释 (`core.py:2532-2534`) | 轮次29 实测 (ROUND_LOG:1419) |
|---|---|---|
| 结论 | 38h **太快**，应放大 16 倍 | 各档升均值只有观测的 **0.46–0.58 倍** ⇒ **太慢** |
| 修法 | 加大 tau | **减小** tau（68→38） |

两者**方向完全相反**，却共存于同一个函数上方。

**冲突 3：注释声称的 16× 修正从未实现**

| 值 | 相对原始的倍数 |
|---|---|
| 原始 | 38（1.00×） |
| 实现过的最大值 | 68（**1.79×**） |
| 注释主张 | ~600（**15.8×**） |

⇒ 即使在第51轮（tau=68 时），注释声称的"慢了 16 倍"与代码实际做的"慢了 1.79 倍"相差 **8.8 倍**。这个缺口从未在 ROUND_LOG 里被讨论过 —— 我按关键词 `600`、`16 倍`、`15.8` 在 34 篇文档里全文检索，**没有任何一篇解释为什么只改 1.79× 而不是 16×**（仅 ROUND_LOG:969 复述了注释）。

**冲突 4：`STATUS.md` 把"未达标读数"记成"验证"**

```

```
该表列名是"验证"，填入的 `51->55` 却是**未达验收线的读数**（验收线是 70，ROUND_LOG:1435）。而 ROUND_LOG:1441 自述"**回归绿但效果未测**"、:1449 自述"逐格…**仍未测**"。

#### 3.1.3 判定

**（实测）三项事实**：
1. 回退 **是刻意且由测量驱动的**：ROUND_LOG:1419-1420 先测出"升均值只有观测的 0.46–0.58 倍（六档同一比例）"，据此判断约束在 `(vpi−V)/tau`，然后才改 68→38。这不是手误回退。
2. 回退**未被完整验证**：逐格口径在轮次 30/31 两度尝试都因内存失败（ROUND_LOG:1449、1504-1505"16 次尝试全部失败"）。
3. 唯一成功的验证**未达验收线**：峰值中位 55 vs 目标 70；ACE 中位 3.00 vs 目标 5.43（ROUND_LOG:1447-1448 vs :1435）。而计划里的补救条款是"若**过冲**则回调到 45-50"（:1436）—— 实际是**欠冲**，该条款不适用，于是**没有任何后续调整记录**，代码停在 38。

**（推断）** 注释里的"600h"与"16 倍"很可能是把**有效时间尺度**（从整条 ODE + 全部 sink + 随机强迫的聚合行为反推）当成了**单一系数** `TAU_INTENSIFY_H`。轮次29 的逐档读数说明：在 38/68 两个取值下，**聚合**增长率分别偏快/偏慢，而 600h 那个数字从没在任何一次模型里被实现过。⇒ 注释把两个不同口径的量并列，是这次矛盾的根源。**该推断未被任何文档确认**，标为 unresolved U1。

⇒ **对任务书问题的回答**：不是"改了没验证的事故"，而是 **"刻意取舍 + 验证从未闭合 + 注释从未同步"**。真问题确实存在，但性质是**验证缺口与注释自相矛盾**，不是"把一个好值误改回去"。第二轮可执行的最小闭合动作：把 `core.py:2532-2534` 的注释改写成"600h 是聚合有效尺度，本模型实测 38h 方向正确但未达验收线（ROUND_LOG:1447）"，或直接删除 600h 那句。

### 3.5 C5：`steering_weights` 从 (vmax, lat) 依赖到常数 —— 刻意的轮次102

**HEAD 版（committed，`git show HEAD:simulator/simcore/core.py:850-862`）**

```python
def steering_weights(vmax: float, lat: float):
    """三层引导权重 (浅层850, 中层, 深层200), 归一化前。

    强度越高越受深层气流引导(环境场深厚), 纬度越高越受低层引导
    (副热带高压/西风带下低层气流主导) -- 与有限区域台风模式的
    深/中/浅层引导权重同构。
    """
    vb = clamp((vmax - 20.0) / 60.0, 0.0, 1.0)      # 20 -> 80 kt
    lb = clamp((abs(lat) - 22.0) / 16.0, 0.0, 1.0)  # 22 -> 38 度
    w_deep = clamp(0.18 + 0.42 * vb - 0.10 * lb, 0.08, 0.70)
    w_shallow = clamp(0.22 - 0.10 * vb + 0.20 * lb, 0.05, 0.45)
    w_mid = clamp(1.0 - w_shallow - w_deep, 0.10, 0.85)
    return w_shallow, w_mid, w_deep
```

**现行版（`core.py:2081-2109`）** 返回常数 `(0.50, 0.25, 0.25)`，两个入参不用。

**来历（medium evidence，ROUND_LOG:1853-1880 + STATUS.md:138,144）**

| 项 | 内容 |
|---|---|
| 缺陷 | "旧式: `w_deep = clamp((|lat|-22)/8, 0, 1)` ⇒ 30N 以上 **200hPa 权重 = 1.0**"，而 200hPa 在 30-40N 的气候平均经向风是 **−4.2kt（向赤道）**，观测台风却以 **+4.6~+9.0kt 向极**移动 ⇒ "台风一到 30N 就被按回去"（ROUND_LOG:1855-1857） |
| 旧表坏掉的铁证 | "那一行的 RMSE 是 **94.08 kt**，而台风实际移速只有 0~20kt —— 数据本身就是坏的"（:1858） |
| 修法 | `tools/calib_steer_sweep.py` 在观测位置做单纯形网格搜索；4 组真实基态权重 g 全部选出 **eff850 = 0.65**（:1870-1877） |
| 为什么取常数 | "**既然纬度变式并不比常数好, 就取常数**(平滑、无带边界跳变、少一个自由参数)"（`core.py:2104`） |

**判定（实测）**：**刻意的、有对照实验的决策**（4 组 g × 单纯形搜索，RMSE 改善），不是漂移事故。⇒ 我第一轮 MINOR-3 的实质问题只剩"**签名里保留两个死参数**"：调用方（`tools/calib_steer.py` 等）会以为有强度/纬度依赖。这是 API 清洁度问题，**不是标定错误**。
