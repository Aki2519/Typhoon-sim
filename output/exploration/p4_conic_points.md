## 0. 一句话

网格色 `(102,204,153)` 加 **逐通道最大绝对差 <= 3** 的二值化，得到 **3418 px** 的虚线网格；
RANSAC 直线束 + 同心圆弧拟合后，投影为 **Lambert 正形圆锥**：
`n = 0.448557`（经线角）/ `0.448550`（纬线半径），`lon0 = 152.3985 degE`，`A = 2955.1775 px`，顶点 `(918.0277, -1768.5631)`。

## 5. 拟合参数（两种等价写法）

`经线角:  sigma = n * (lam - lam0)
         n = 0.448557      lam0 = 152.3985 degE
         角残差 RMS = 0.000773 deg   最大 = 0.001507 deg

纬线半径: rho(phi) = A * tan(pi/4 + phi/2)^(-n)
         n = 0.448550      A = 2955.1775 px
         半径残差 RMS = 0.003156 px   最大 = 0.004873 px

=> 两路独立来源的 n 相对差 = 1.590e-05`

**像素 -> 画布**（基准图原生尺度，scale=1）：

`sigma = radians(n * (lam - lam0))
x = apex_x + rho(phi) * sin(sigma)
y = apex_y + rho(phi) * cos(sigma)`

### 三个候选族的对比（同一批 6 条纬线，自由参数最小二乘）

| 族 | 公式 | RMS 残差 | 最大残差 |
|---|---|---|---|
| **Lambert 正形圆锥** | `rho = A*tan(pi/4+phi/2)^(-n)` | **0.0032 px** | **0.0049 px** |
| 等距圆锥 | `rho = A - B*phi` | 3.8162 px | 4.8901 px |
| Albers 等积 | `rho = A*sqrt(C - D*sin phi)` | 7.5507 px | 9.7349 px |

逐环 Lambert 残差 (px) = [0.0001, -0.0035, 0.0049, 0.0025, -0.0042, 0.0002]

## 6. 残差的**口径**说清（最容易被误读的地方）

我报过「0.003 px」，但那是**参数级拟合残差**，不是逐像素残差。两个口径都给：

| 口径 | 定义 | 数值 |
|---|---|---|
| **A. 半径律残差** | `A*t(phi_j)^(-n) - rho_j`，6 条纬线 | RMS **0.0032 px**，max 0.0049 px |
| **B. 角度律残差** | `n*(lam_k - lam0) - sigma_k`，8 条经线 | RMS **0.000773 deg** 约 **0.040 px** @rho=2968 |
| **C. 逐线像素残差（经线）** | 内点到拟合直线的垂距 RMS | **0.090-0.119 px**（8 条） |
| **D. 逐弧像素残差（纬线）** | `rho - rho_j` 的标准差 | **0.101-0.286 px**（6 条） |
| **E. 顶点一致性** | 8 条经线到公共顶点的距离 | max **0.071 px** |

**A/B 远小于 1 px，是因为它们只在参数空间里比较 6 个半径 / 8 个角度**；C/D 才是像素级，量级 0.1-0.3 px，
受限于**像素栅格与虚线渲染**（一条 1 px 宽的抗锯齿虚线，其最亮像素本身就有 ±0.5 px 量化）。
两者不矛盾，但不能互相冒充 —— 请 sim-run 明确引用哪一个。

### sim-run 复算建议的三种比法（从强到弱）

1. **比掩码**：用 §1 的判据与你自己的容差，比较掩码 sha256 与像素数；容差不同就先对齐到 tol=3 或报告差异。
2. **比参数（最独立）**：你自己从掩码拟合 8 条直线（RANSAC / Hough）与 6 个同心圆，比 `sigma_k`、`rho_j`、顶点。
   两边各自提取，只在参数层面比 —— 这正是你提的「两边各自提取 -> 比点 / 比参数」。
3. **比交点**：用你拟合出的参数重算 48 个交点，与 §7 表格逐点比欧氏距离。

**警告：不要**直接拿「预测交点 -> 最近掩码像素」的距离当残差。掩码是**虚线**（最大连通块仅 10 px），
很多交点的预测位置正好落在**划与划之间的空隙**里，那个距离会到 10+ px —— 那是**采样几何假象**，不是拟合误差。
要这么比，请先在空隙处插值补线，或只统计「预测点 3 px 邻域内存在掩码像素」的比例。

## 8. 给 sim-run 的轨迹验证数据（它卡住的那一步）

它用 `min(RGB)>190` 提了 4055 px 白掩膜，双向 chamfer 得 pred->white 平均 438 px / white->pred 平均 6.8 px，
自相矛盾 => 它判断「掩膜不是连续轨迹，ICP 作废」。**这个判断是对的**：
`min(RGB)>190` 会把**经纬度标注文字** `(202,218,210)` 和水印的亮像素都收进来，而那些是**离散的**。

**正确的提法（我实测过，给出 px 数）**：

`MARK = [(94,186,255),(255,193,64),(255,231,117),(255,143,32),(102,204,153),
        (255,255,204),(0,250,244),(255,96,96),(255,135,135)]   # 9 个标记色, 采样自原图
mk = np.zeros((H,W), bool)
for cc in MARK: mk |= (np.abs(a - np.array(cc)).max(axis=2) <= 12)          # -> 30180 px
white = (a.min(axis=2) >= 215) & (a.max(axis=2) - a.min(axis=2) <= 25)   # 细白连线 -> 1043 px
ink = mk | white                                                        # -> 31223 px
dt = ndimage.distance_transform_edt(~ink)`

| 掩膜 | 像素数 | 说明 |
|---|---|---|
| 9 个标记色 ±12 | **30180** | 轨迹主体在**标记**上，不在连线上 |
| 细白线 (min>=215 且 max-min<=25) | **1043** | 标记把线盖住了，白线本身很碎 |
| **并集 ink** | **31223** | **用它做距离变换** |

用真实 `bwp122026.dat`（99 点）投影后查 `dt`：

| 项 | 值 |
|---|---|
| 落在画布内 | **99 / 99** |
| 残差中位 | **0.00 px** |
| 残差均值 | 0.02 px |
| p90 | 0.00 px |
| 最大 | **1.00 px** |

**分辨力上限（必须一起写）**：标记直径约 20 px，所以这个口径只能分辨到 **约 ±10 px**。
我也试过「只比细白线」，结果**没有分辨力**：原样中位 10.44 px，而把整条轨迹**右移 8 px** 反而降到 5.00 px
（标记遮住线，投影点落在标记中心，离最近白色像素本来就远）。**所以那个口径不能用来判 PASS/FAIL。**
轨迹的**箭头级**精度判据由经纬网提供（§6 的 A/B/C/D），轨迹这条只作**一致性佐证**。
