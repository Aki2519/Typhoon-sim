## 2. 抗锯齿判据（本轮核心）

### 2.1 口径（先定义，再算）

```
mid_alpha(surf) = count( 0 < alpha(surf) < 255 )       # 必须画在【全透明】面上
```
- **必须透明面**：画在已填充不透明面上，`get_at()[3]` 恒为 255 ⇒ mid 恒为 0 ⇒ 会得出"AA 没生效"的**假结论**（简报已警告）。
  本报告的绘画路径一律传 `bg_color=(0,0,0,0)`（`paint_render.py:274-275` 的 `bg = self.bg_color or (200,220,240)`
  在传四元组时走 `surf.fill((0,0,0,0))`）⇒ 画布透明，判据成立。
- 另记 `ink_px = alpha>0`、`core_px = alpha>=128`：**加了 AA 之后 `core_px` 应基本不变、`ink_px` 变大**
  （BEFORE 两者**完全相等**，见 §2.3）——这是"只平滑边缘、不改变几何"的判据基础。
- **导出大图**：渲染后 `pygame.image.save` → **重新 `load` 再量一次**（`reloaded_mid`）⇒ 判据覆盖"导出路径"，不只预览。

## 5. 我用了什么测法 / 允许的结论强度

- **允许（本报告的判定只用这些）**：中间 alpha 像素数（透明面）、`ink/core` 像素数与掩膜 sha、
  二值 IoU/质心漂移、逐像素相同率、主色直方图、图元调用点计数、`free_hash` 指纹、pytest 结果。
- **不允许**：任何耗时/加速比结论。`p6_reg.py` 里的 `sec` 只用于"是否 timeout"，**不参与任何判定**。
- **内存纪律**：全部单进程顺序跑（本机 0.7–2.6 GB 波动）。`p6_ty4.py` 载入底图（10800×5400）时峰值约 250 MB；
  `p6_reg.py` 的 `test_paint` 会构造 6 次 `TySim`。三者**没有并发**。
- **口径必须写死**：AA 面尺寸（96×96 不裁）、底图窗口搜索半径（±8 px）、ink 阈值（max|Δ|>8）、
  主色量化（16 级）。改任何一项都可能得出不同数字（§2.2 的 180/352 就是实例）。
