# 核爆扰动注入方案（WRF 中途爆炸实验）

> 目标：在真实 WRF 模拟**进行到指定时刻时**，于台风附近注入一个类似"氢弹爆炸"的极端局部扰动，然后**继续积分**，观察台风被炸开/眼墙崩溃/强对流激发的效果。
> 本方案只做设计，不含实现代码。实现时沿用现有 `simulator/wrf/` 管线与 `bogus_vortex.py` 的成熟写法。

---

## 1. 结论与物理限制（先说清能做到什么）

| 项 | 说明 |
|---|---|
| 能做 | 在 WRF restart 场里，于指定位置叠加一个极端局部的**热 + 动量 + 位势**扰动，然后续跑 |
| 不是真实核爆 | WRF 是大气模式，不含火球辐射、超音速冲击波、气化等过程；注入的是"理想化热爆炸" |
| 最关键的物理限制 | **网格尺度稀释**：dx=30km 单格空气约 10¹⁶ kg，一颗 10 万吨 TNT（4.2×10¹⁴ J）注入后只升温 ~0.04 K，几乎无感 |
| 对策 | 强度**参数化**：提供"真实量级"与"放大档位"，放大档位（升温几百~几千 K、气压骤降几十 hPa、径向风 100+ m/s）才能在 30km 网格看到台风被打散 |
| 建议 | 若要看"贴近真实核爆"的效果，需同时把域加密到 ~1km（dx 由 30000 改 1000，计算量数十倍），否则用放大档位做"理想化爆炸" |

---

## 2. WRF 分段重启（restart）机制

现有 `run_wrf.sh` 是 `wrf.exe` **一次性**跑完（`namelist.input.template` 里 `restart = .false.`）。要做"中途注入"，必须改成**两段**：

### 2.1 第一段（跑到注入时刻）

`namelist.input` 修改：

```
&time_control
 restart           = .true.,
 restart_interval  = __SEG1_MINUTES__,   ! = 注入时刻 − 起点（分钟）
 io_form_restart   = 2,                  ! NetCDF
 start_*           = 起点,
 end_*             = 注入时刻,
/
```

WRF 到达 `restart_interval` 的时间点会写出 `wrfrst_d01_YYYY-MM-DD_HH:MM:SS`。

> 说明：`restart_interval` 是"从起点起每隔 N 分钟写一次 restart"。只要注入时刻能写成 `N` 的整数倍，第一段结束时恰好得到一个 restart 文件；否则可设 `restart_interval=1`（每 1 分钟写一个，选最后一个），代价是写盘变多。

### 2.2 注入扰动

对刚生成的 `wrfrst_d01_*` 运行新脚本 `inject_burst.py`（见 §5）。

### 2.3 第二段（从注入时刻续跑到终点）

`namelist.input` 修改：

```
&time_control
 restart  = .true.,
 start_*  = 注入时刻,
 end_*    = 终点,
/
```

`wrf.exe` 会读入被改过的 `wrfrst_d01_注入时刻` 作为初始场继续积分（无需重跑 real.exe，`wrbdy_d01` 仍沿用第一段的边界）。

> 备选：若不想依赖 `wrfrst`，`wrfout_d01_注入时刻` 本身也含 restart 所需变量，可复制为 restart 输入；但标准做法是 `wrfrst`。

## 3. 总体流程（改动点）

```
第一段 wrf.exe（到注入时刻）
        │
        ▼
wrfrst_d01_<注入时刻>
        │
        ▼
inject_burst.py（在指定位置叠加"爆炸"扰动）      ← 新增
        │
        ▼
第二段 wrf.exe（restart 续跑到终点）
        │
        ├─► track_vortex.py（追踪：路径/中心气压/最大风速/R34）  ← 现有
        └─► wrfout_to_fields.py（→ env/wrfdir/*.npz）           ← 现有
```

改动最小集：
1. `run_wrf.sh` / `run_wrf.ps1` 增加"分段重启 + 注入"分支（新参数 `-Burst` 之类）。
2. 新增 `simulator/wrf/inject_burst.py`。

## 4. 注入位置（三种模式，均支持）

| 模式 | 输入 | 说明 |
|---|---|---|
| 手动经纬度 | `--lat --lon` | 与 `bogus_vortex.py` 一致 |
| 台风中心 | `--track track.json --at "2026-08-05 12"` | 读 `track_vortex.py` 输出的 `track.json`，取指定时刻台风中心 |
| 中心相对偏移 | 上述基础上加 `--dx_km --dy_km` | 以中心为原点，东为正、北为正的偏移（默认 0,0 即正中） |

## 5. inject_burst.py 设计（爆炸扰动形态）

仿照 `bogus_vortex.py`，但扰动形态由"气旋"改为"爆炸"。修改 `wrfrst` 中的：

| 变量 | 爆炸形态 | 参数 |
|---|---|---|
| `T`（扰动位温） | 核心最强、径向/垂向高斯衰减 | `dt_core`（K）核心升温、`r_burst`（km）水平半径、`zc`（m）垂向特征高度 |
| `U` / `V` | 径向**向外**冲击流（离中心发散） | `v_burst`（m/s）最大径向风速 |
| `W`（垂直速度） | 核心强上升 | `w_burst`（m/s）最大上升速度 |
| `PH`（位势扰动） | 核心位势抬高 → 等效气压骤降 | `dp_core`（hPa）等效气压下降 |
| `QVAPOR` | 核心水汽扰动（可选，模拟被炸出的水汽/降水） | `dq_core`（kg/kg） |

### 5.1 空间形态（极坐标，以注入点为圆心）

```
r = 水平距离（km）
z = 高度（m，由 PHB 反算）

ΔT(r,z)   = dt_core · exp(−(r / r_burst)²) · exp(−(z / zc)²)
U_r(r,z)  = v_burst · (r / r_burst) · exp(−(r / r_burst)²)   # 中心 0、近中心达到峰值、远处衰减
W(r,z)    = w_burst · exp(−(r / r_burst)²) · exp(−(z / zc)²)
PH_anom(r)= 由 dp_core 经静力关系换算的位势扰动
```

- 核心温度最高的点应与台风中心（或指定点）重合。
- 所有量都做成**叠加到原场**（与 `bogus_vortex` 一致），不覆盖原场。
- 南北半球无需区分（爆炸无旋转方向）；但如需"旋转爆炸"可加切向分量，默认不加。

### 5.2 质量-风一致性

`bogus_vortex.py` 的注释已指出：WRF 里直接改 `P` 会与 `T` 不一致。爆炸场景同样**只改 T/U/V/W/PH/QVAPOR**，气压的精确自洽由 WRF 初始化时自我调整；`dp_core` 通过 `PH` 位势异常间接表达"爆炸低压"，并在文档里标注为近似。

## 6. 参数表（全部可配，覆盖"真实"与"夸张"两档）

| 参数 | CLI | 真实量级（参考） | 夸张档位（30km 网格可见） | 单位 |
|---|---|---|---|---|
| 核心升温 | `--dt_core` | 0.04 ~ 5 | 500 ~ 3000 | K |
| 径向冲击风速 | `--v_burst` | 1 ~ 20 | 100 ~ 200 | m/s |
| 上升速度 | `--w_burst` | 0.1 ~ 2 | 30 ~ 80 | m/s |
| 等效气压下降 | `--dp_core` | 0.1 ~ 2 | 20 ~ 80 | hPa |
| 扰动水平半径 | `--r_burst` | 3 ~ 15 | 60 ~ 150（≥2 个格点） | km |
| 垂向特征高度 | `--zc` | 3000 | 5000 ~ 8000 | m |
| 水汽扰动 | `--dq_core` | 0 | 0.005 ~ 0.015 | kg/kg |
| 注入位置 | `--lat --lon` / `--track --at` / `--dx_km --dy_km` | — | — | — |

> 经验：`r_burst` 必须 ≥ 2~3 个网格距（30km 域下 ≥ 60~90 km），否则扰动只落在单格、被数值耗散掉。

## 8. 时间成本与磁盘

- **积分时长不变**：分段重启不会明显增加总积分时间（两段合计 = 原来一整段；仅多一次 restart 读写，秒级）。
- 30km 域 10 天 3–10 小时（现有 README 数值）；若为看清爆炸改 dx=1km，时间/磁盘增加数十倍，需提前评估。
- `wrfrst_d01` 单个文件约 = 一个 wrfout 大小（数十 MB）。

---

## 9. 风险与注意事项

1. **数值爆炸**：升温几千 K + 径向风 150 m/s 可能触发 CFL 不稳定，必要时第二段减小 `time_step`（如 150→60）。
2. **边界约束**：爆炸若离侧边界太近，扰动会与 `wrbdy` 的松弛区冲突；建议注入点距边界 ≥ 10 个格点。
3. **气压自洽近似**：`dp_core` 是位势近似，实际 MSLP 下降量由 WRF 自调后偏小，属预期。
4. **追踪脚本适配**：爆炸后若台风中心散架，`track_vortex.py` 可能追踪失败/跳变，需容忍无追踪结果、仅看场动画。
5. **CDS/ERA5 依赖**：分段重启不改变场下载，仍走现有 `fetch_era5.py`。

---

## 10. 验收建议（实现后）

1. 空跑：无扰动时两段重启结果 ≈ 一次跑完结果（误差极小），验证 restart 正确。
2. 爆炸实验：注入点周围出现强上升/风暴，台风眼墙被打散或路径偏转，可从 wrfout 场动画与 `track.json` 强度下降验证。
3. 参数扫描：真实档位 → 几乎无变化（符合预期）；夸张档位 → 明显打散（符合预期）。
